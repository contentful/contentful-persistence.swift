# AGENTS.md

Orientation for coding agents working in `contentful-persistence.swift`. Humans
should read [ARCHITECTURE.md](ARCHITECTURE.md) and
[CONTRIBUTING.md](CONTRIBUTING.md) as well.

## What this repository is

A Swift library that persists data from a Contentful space into a local CoreData
database. It drives the Content Delivery API `/sync` endpoint through the
official [contentful.swift](https://github.com/contentful/contentful.swift) SDK
and writes the results into `NSManagedObject` subclasses that the host app
declares. The library is consumed as `ContentfulPersistenceSwift` on CocoaPods,
as a Carthage dependency, and as a Swift Package.

The public module name is `ContentfulPersistence`; the pod name is
`ContentfulPersistenceSwift`. They are deliberately different — see
`ContentfulPersistenceSwift.podspec` (`spec.module_name`).

## Ground rules for agents

- **Do not run installs, builds, or the test suite unless you were asked to.**
  The suites need Xcode with the iOS/tvOS/macOS toolchains and a Carthage
  bootstrap; `make setup` and `carthage update` mutate the machine.
- **Never invent commands.** Every command that exists is in `Makefile`,
  `fastlane/Fastfile`, `Scripts/`, or `.circleci/config.yml`. If it is not
  there, it is not a command this project supports.
- **Four build systems must stay in sync.** A change to the dependency floor on
  `contentful.swift` has to be made in `Package.swift`,
  `ContentfulPersistenceSwift.podspec`, and `Cartfile` together. Commit
  `Package.resolved` / `Cartfile.resolved` alongside.
- **Do not hand-edit the version.** `Config.xcconfig`, `.env`, and `.envrc` are
  all written by `Scripts/set-version.sh`. The podspec reads
  `ENV['CONTENTFUL_PERSISTENCE_VERSION']` via `dotenv`.
- **Do not touch `docs/` outside `docs/ADRs/`.** Everything else under `docs/`
  is Jazzy output regenerated by `Scripts/reference-docs.sh`.
- **Do not weaken `.swiftlint.yml`.** It already disables a specific, deliberate
  set of rules; adding to that list to silence a new warning is not the fix.
- **`Tests/` is excluded from SwiftLint** (`.swiftlint.yml` `excluded:`), so
  lint passing says nothing about test-file style.

## Where behaviour actually lives

Start at `Sources/ContentfulPersistence/SynchronizationManager.swift` (~925
lines, the largest file by a wide margin). It implements
`Contentful.PersistenceIntegration`, so the SDK client calls into it as sync
pages arrive. Everything else is a collaborator of that class:

- `PersistenceStore.swift` — the storage protocol the manager writes through.
- `CoreDataStore.swift` — the only shipped implementation of that protocol.
- `Persistable.swift` — `PersistenceModel` plus the `EntryPersistable` /
  `AssetPersistable` / `SyncSpacePersistable` protocols the host app conforms to.
- `Relationships/` — link resolution that survives unpublish/republish.
- `DataCache.swift` — `NSCache`-backed lookup, with a `NoDataCache` variant that
  reads straight through to the store.

## Conventions to match

- File headers use the `//  <Filename>.swift` / `//  ContentfulPersistence` /
  `//  Created by …` / `//  Copyright © <year> Contentful GmbH.` block. Newer
  files (`Relationships/`) use the shortened two-line form. Match whichever
  form the neighbouring files use.
- Public API is documented with `/** … */` blocks using `- parameter`,
  `- throws`, and `- returns`. Keep that style rather than switching to `///`
  for public symbols.
- `line_length` warns at 150 with comments and URLs ignored; `file_length`
  warns at 800; `function_body_length` at 110.
- Changes that ship go in `CHANGELOG.md` under
  "Merged, but not yet released". The changelog is hand-maintained and
  organised by release with a table of contents at the top — update both.
- Commit prefixes in recent history are `feat:`, `fix:`, `chore:`, and `docs:`.
  Reference the Jira key in brackets when there is one, e.g.
  `chore: set up Renovate for dependency updates [MEC-3447]`.

## Things that will surprise you

- The default branch is **`master`**, not `main`. `.github/workflows/codeql.yml`
  and `Scripts/release.sh` both hard-code `master`.
- `.env` is **tracked** and contains only
  `CONTENTFUL_PERSISTENCE_VERSION`. It is a version carrier, not a secrets file.
  `.envrc` is gitignored. Do not add anything else to `.env`.
- `README.md` still tells SPM users to depend on the `master` branch rather than
  a tagged version.
- The README badges point at Travis CI. Travis is gone; the surviving config is
  `old-travis-integration.yml` and `Scripts/travis-build-test.sh`, kept as dead
  reference. CI is CircleCI (`.circleci/config.yml`).
- There is a `ContentfulPersistence_watchOS` scheme in the Xcode project, but
  CircleCI only runs iOS, macOS, and tvOS. watchOS is built but not tested in CI.
- Test HTTP stubbing uses `mariuskatcontentful/OHHTTPStubs`, a fork, pinned in
  `Cartfile.private` and vendored as a submodule.
